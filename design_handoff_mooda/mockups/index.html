검색 인풋이 지도 위의 작은 상단 바 — "뭘 검색해야 하지?" 플레이스홀더 전략 부재

PWA에서 앱을 켰을 때 사용자는 보통 "여기 근처 조용한 곳"을 찾으려 함. 지금은 플레이스홀더가 "카페 검색"처럼 일반적이라 사용자가 지역명과 분위기를 한 번에 입력해야 할지 모름. 또 인풋 탭 → 키보드 올라옴과 동시에 지도가 키보드에 가려져 맥락이 사라짐.
개선(리디자인 반영): 인풋 탭 시 full-screen 검색 화면으로 전환 (네이버지도 방식). 플레이스홀더는 "성수동 조용한 카페"처럼 예시형. 입력 중에는 최근 검색, Kakao Local 자동완성, Mooda DB 등록 카페를 3 섹션으로 분리.

지도 bounds 변경마다 RTK Query 재요청 — 모바일 데이터 소진

useGetNearbyCafesQuery가 중심 좌표·줌을 키로 받아 미세한 드래그마다 재페치. PWA 모바일에서 초당 10+ 호출이 쉽게 발생.
개선: (1) geohash 6자리 버킷으로 중심 좌표를 양자화해 캐시 키 안정화 · (2) 드래그 종료 후 300ms debounce · (3) 자동 페치 대신 "이 지역 재검색" 버튼으로 명시 트리거 · (4) keepUnusedDataFor: 120으로 뒤로가기 때 재요청 방지.
store/api/cafeApi.ts
Crit

카카오맵 JS SDK가 페이지마다 재로드됨 가능성 (SSR 경계)

Next.js 16 App Router에서 map 컴포넌트를 Client에서 매번 마운트/언마운트하면 SDK 스크립트가 중복 삽입되거나, 핸들러가 leaked됨. /map → 상세 → 뒤로 시 GC 안 됨.
개선: (1) SDK 로드는 app/layout.tsx에서 next/script strategy="afterInteractive"로 전역 1회 · (2) 맵 컴포넌트는 dynamic(() => import..., { ssr: false })로만 로드 · (3) unmount 시 kakao.maps.event.removeListener로 리스너 정리 · (4) 상세로 이동 시 맵 인스턴스를 useRef로 유지 & keepMounted 패턴.

상단바 · 바텀시트가 safe-area-inset 미적용
